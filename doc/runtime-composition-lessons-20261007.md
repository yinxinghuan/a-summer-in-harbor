# RPG composition lessons from the published harbor

Keep one authority and one final runtime factory. A content module consumes the existing life assembly once; it does not rebuild plants or animals. Preserve final wrappers in order: life/content, frozen news, motion, foreground settlement, guarded account authority. New optional save roots survive all whole-head actions and old compatible readers.

A business action first settles only confirmed foreground budget in its candidate head, then checks current resident presence, opening hours, order due time and goods. Commit both through the original CAS/receipt. A gameplay failure commits neither budget nor goods. Lost response uses the exact original ID. Pre-validation happens before prepare: finite domain failures there need explicit terminal identity too. Unsupported saved data, clock configuration and infrastructure failures remain recoverable.

Projection validity uses its real journey/scope/epoch, original version/cursor/minute and all semantic inputs. Adding plant-use or relationship roots requires adding them to that content key. A harmless clock ACK may reuse an old correctly stamped DTO; a changed order/relationship/current proof must show the old view only while disabling its actions until a verified read arrives. Never rewrite an old DTO stamp to call it current.

Read actor feet, logical room and binding from the actual renderer and final saved position. Do not replace a motion parameter with a content clock port. Keep a separate options argument; content clocks read the already committed minute. Continuous render coordinates do not replace logical save coordinates. Movement confirmation never renews an observation proof.

For legacy relationship migration, read is pure. First legitimate action commits the optional rule pin and legacy facts with the original reward transaction. Historical facts without dates stay undated; a large old relation score does not manufacture social days or a new stage. AI may choose only admitted authored lines and never points, stages, inventory or rule actions.

Build one source commit for both frontends and retain the one shared backend. Compare all deployed file hashes, the backend image/bundle and source marker. Validate private backups and every table digest while the writer is stopped; expose the candidate only after exact preservation. After exposure, preserve new state and use compatible code, never an old database snapshot. Separate local synthetic renderer/PG, ordinary external guest, real platform account and physical phone claims.


### Native observation and menu integration

The native crab uses its own versioned optional root and scoped art pin. An observation is evidence of the server-confirmed player position and a stationary native frame after a bounded wait. A client-reported pose or an earlier motion version cannot mint knowledge. Receipt failure must roll back the proof, record and relationship reward together. Compact foreground confirmations retain only the latest native frame, and opening or reconnecting a clock never advances offline time.

The geometry guard includes the complete visible sprite envelope and current old animal/NPC routes; ground bodies also participate in the authoritative swept movement check. Atlas-only or isolated renderer approval does not replace actual Main, account HTTP, database and menu validation.

Four main menu sections share the existing paused-world, identity and pending-action boundaries. Creating a separate journey preserves the entire prior head and retries the same enrollment after a lost response. Switching back must restore module roots and reset renderer state by journey identity. Knowledge belongs with bag records rather than inventory quantities. The release checks both the former gameplay flows and these new navigation paths on one final build.
