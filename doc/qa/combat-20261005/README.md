# 训练退出与操作引导修复（本地，未部署）

## 范围与复现

以已发布 `02dd6db5446b02dd4f347a42684fff6ab25aca44` 为基线。按授权协调任务复现训练退出绿屏；仅本机合成玩家、SQLite、现有素材，不改生产后台、账号、作物或新闻。

2026-10-05：320×568、390×844 均通过真实 UI 进入友好切磋、开始、移动、出手、停止、关闭对话后复现。截图 `before/returned-*-platform-layout.png`，刷新恢复见 `before/refreshed-*`。`before/report.json` 保留完整原始错误和场景树。

根因：`Combat.tsx` 的 `Application.destroy(true, {children:true})`。本项目固定 Pixi 8.20.1 中，renderer destroy 的布尔 true 同时触发 `GlobalResourceRegistry.release()`，清除跨 renderer 共用 batch pool。RPGJS 世界仍有 canvas、完整场景树和有效 WebGL context，却因 `_BatcherPipe.execute` 读取已清除 batch 的 `geometry` 抛错而停止绘制。不是图片下载失败，也不是退出时销毁了世界 DOM。

先修最小生命周期错误：只 removeView、不 releaseGlobalResources；每次异步加载完成都检查取消；释放训练专属帧对象但保留全局缓存纹理。验证同一操作恢复后，再改善训练信息呈现。
