# 雨后事实准备的可复用经验

- 先验证现有policy pin与已提交分钟，再推导过去雨段；读取不是观察动作，不创建记录或补算离线。
- 范围ID包含旅程与policy，episode ID跨同段读取稳定；snapshot version另校验，不能用稳定ID接纳过时模型结果。
- “雨结束”和“原薄荷已恢复”是两份不同事实。不能仅凭当前recoverAt把全部恢复归功于雨，更不能描述新植物出现。
- 线索必须使用已经观察过的既有定义/geometry，保留老版本档案；信息提示不等于收集、奖励或素材准入。
- 模型结构化选择与自然语言生成分开验收。有限topics/effects=[]可机械拒用不支持能力；手写编译不是实际AI可用性证明。
- 对话context沿原居民生活、关系、任务与有日期的真实资讯来源追加天气证据，不用天气摘要替代人物或给旧资讯改日期。
- dry adapter默认关闭，调用方必须提供原authority完整准入链；本地基础guard证明不能冒充最终B2/clock事务或真实登录。
- 所有进入模型的context复制后冻结，不能因只读context冻结或修改原head对象。

## 原 authority 与 Main 接线后的经验

- “不调用模型”仍需原业务事务：空间、已认识/在场、pending、CAS、前台分钟结算都保留；不能用一个新按钮的前端检查代替。
- 新业务错误不只是文案表。必须明确列入原HTTP终态分类；否则合法拒绝会被包装为基础设施503，让客户端永久保留原pending。实际HTTP与重新选择的恢复路径一起验，不扩大为所有大写错误都终态。
- 保存普通规则回应时用原talk history，不加question字段或首次AI成功标记。真实AI能力与规则可用性分开记，原互联网资讯仍带其实际日期和到期提示。
- 同一分钟也可能发生policy首次pin；投影缓存键必须纳入实际pin，而非只看分钟与位置。
- 回包丢失要重放同一action_id；确定拒绝后的用户新选择要产生新action_id。二者的相反处理均由原事务回执证明。
- 首次截图误采到原180ms淡入中间帧不代表正文常态对比度。截图等待实际动画完成，保留旧证据，再用同尺寸同状态对照。
- UI错误仍沿原可滚动面板底部呈现；截图与恢复验证须实际滚动到错误或回应，DOM可见断言不能代替画面可见。
- 本地合成identity只用于独立fixture，不能接触正式入口或玩家原存档，不能把它当正常登录QA。测试PG仅使用白名单本机新建fixture，结束即停。
- 磁盘紧张时，只能回收自己的可重建缓存。用独立APFS写时复制保留自身dist原字节可减少重复块，不能对原正式构建做编辑，也不能把普通硬链接当独立副本。
